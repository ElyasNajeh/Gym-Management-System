# GymFlow — Gym Management System

## Project Overview

GymFlow is a Windows desktop application for managing gym members, subscription plans, annual subscriptions, and payments. It uses shared in-memory services behind a modern WPF interface, so application data lasts for the current session only.

## Features

- Add, search, update, and safely delete members and subscription plans.
- Create subscriptions from existing members and plans and review member history.
- Record payments using the existing cash, card, bank-transfer, and wallet implementations.
- Search payments and filter them by subscription.
- Preview, validate, and import members or subscription plans from `.xlsx` and tab-separated `.txt` files.
- Detect malformed rows and duplicates before import and report row-level results.
- View a dashboard calculated from current service data.

## Technologies

- C# 12
- .NET 8 (`net8.0-windows`)
- WPF and XAML
- NuGet, MSBuild, and the .NET CLI
- Built-in `System.IO.Compression` and LINQ to XML for `.xlsx` reading

No third-party packages are required, and Microsoft Excel does not need to be installed.

## OOP and SOLID

Domain models encapsulate their validation, while services own member, plan, subscription, and payment operations. `SubscriptionService` and `PaymentService` use constructor-injected collaborators, and all WPF screens share the same service instances. `IPaymentMethod` supports polymorphic cash, card, bank-transfer, and wallet processing. `DataImportService` keeps file parsing and import coordination separate from the domain services and uses the existing validation and service APIs instead of bypassing business rules.

## How to Run

Requirements: Windows 10 or 11 and the .NET 8 SDK.

```powershell
dotnet restore .\GymManagementSystem.csproj
dotnet build .\GymManagementSystem.csproj --configuration Release
dotnet run --project .\GymManagementSystem.csproj
```

Publish a self-contained Windows x64 application:

```powershell
dotnet publish .\GymManagementSystem.csproj --configuration Release --runtime win-x64 --self-contained true --output .\publish\win-x64
```

The application and sample `data` directory are written to `publish\win-x64`. WPF is Windows-specific.

## Importing Data

Open **Import data** from the sidebar, choose **Members** or **Subscription plans**, and select an `.xlsx` or UTF-8 tab-separated `.txt` file. Review the row-level preview, then confirm to import valid rows. Invalid and duplicate rows are skipped without overwriting existing records.

Ready-to-use examples are available in `data\members.txt`, `data\members.xlsx`, `data\subscription_plans.txt`, and `data\subscription_plans.xlsx`. IDs and dates continue to be generated by the application. Imported data remains in memory and is not persisted after the application closes.

## Project Architecture

```text
Gym-Management-System/
├── App.xaml(.cs)              # WPF startup, resources, and shared services
├── MainWindow.xaml(.cs)       # Application shell and navigation
├── data/                      # Import-ready TXT and Excel examples
├── importing/                 # Safe file parsing, validation preview, and import coordination
├── interfaces/                # Payment method abstraction
├── models/                    # Validated domain entities
├── services/                  # Existing in-memory business operations
│   └── paymentMethods/        # Polymorphic payment implementations
└── ui/
    ├── Dialogs/               # Member, plan, subscription, and payment forms
    ├── ViewModels/            # UI-only joined display records
    └── Views/                 # Dashboard, management, and import pages
```
